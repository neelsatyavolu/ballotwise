# DDHQ private egress

Cloudflare Container transport for Ballotwise's optional Votes connection. The Worker has no public route or workers.dev endpoint. Ballotwise calls it through its `DDHQ_EGRESS` service binding, targeting service `ballotwise-ddhq-egress`.

The binding accepts `GET` requests for `/api/searchv2`, `/api/vote-history?race_id=…`, `/api/forecast/<id>`, and `/api/races/<id>` with exactly one `Cookie: __session=…`. Search requires `q`, `filterYear`, `filterState`, and `filterOffice`. Other headers and request bodies are not forwarded. The relay derives `Authorization: Bearer …` from that same validated session value because Clerk's cookie flow expects browser cookie context. A separate caller Authorization value is never accepted. Only the fixed Votes origin is contacted; redirects are rejected.

The three fixed `/forecast/2026/{house,senate,governor}` pages are also allowed, with no query parameters. Those requests negotiate React Server Component data with `RSC: 1`. Ballotwise extracts validated published forecast records, chamber totals and history; account/bootstrap properties and raw pages never reach clients or persistent storage. A changed payload shape fails closed to the public fallback. Governor forecasts have race ratings but no aggregate projection or chamber history.

Boards use the observed `/api/races/batch/topline?ids=…` feed, restricted to 1–24 comma-separated numeric IDs and no other query keys. This returns current counts, calls and reporting for the requested seats in one request; per-race forecasts come from the separate private bulk forecast feed. Only public race-ID mappings are kept between requests, never results. Full race detail still uses `/api/races/<id>` for county data. A completed 2024 race and its batch response confirmed the winner/call timestamp, percentage-point units, total-vote and precinct fields; future election-night corrections are covered with synthetic sequences of that observed schema, not claimed as live events already witnessed.

Ballotwise's private board route accepts up to 512 seats in one authenticated pass. It mints one session token, primes missing public ID metadata from the needed fixed forecast pages on a cold large pass, then issues groups of at most 24 IDs at concurrency four. If a metadata page is unavailable it falls back to the existing four-way race lookup; no forecast body is cached. Temporary failures clear only the affected group's count rows, while authentication failures propagate. After token minting, a 25-second deadline and the caller's cancellation signal bound the whole pass; a deadline ends with temporary 502 rather than letting a long fallback outlive the short-lived session JWT. The egress URL allowlist remains capped at 24 IDs per upstream request.

One warm `curl_cffi` async client reuses connections with eight handles. Cookies and the matching Bearer header are passed per request, server cookies are discarded, and neither credentials nor response JSON are written or logged. Every response is private and uncached. Real upstream statuses, including 401, 403, and 429, are preserved; transport failures and invalid successful responses become 502. Only `signed-in`, `signed-out`, and `handshake` values of `x-clerk-auth-status` are forwarded; Clerk's detailed reason/message headers are stripped.

Run the offline tests from this folder with `npm test`. They use Python's standard library and require neither curl_cffi nor network access. Install the separate Worker dependency with `npm ci`. An authorized deployment uses `npm run deploy`; it requires Docker and the root repository's Wrangler installation. Deploy this service before deploying a Ballotwise binding that references it. The migration in this service's config creates its Container Durable Object, not a D1 migration. Deploying this service does not deploy the main Ballotwise app; those application changes remain separate and uncommitted until explicitly authorized.

The unsigned forecast and dummy-session history probes passed remotely on 2026-10-31 using Chrome 131 impersonation and API fetch metadata. A real Pro connection and Senate, House, governor, and repeated refresh requests were subsequently verified with a fresh emailed code, without logging or storing that code.
